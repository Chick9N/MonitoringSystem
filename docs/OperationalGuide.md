# 运行与验证手册

## 运行日志

应用启动后将 Qt 日志写入 `%LOCALAPPDATA%/MonitoringSystem/logs/monitoring.log`，单文件达到 5 MiB 后保留一份轮转文件。主界面“查看日志目录”按钮可以直接打开日志目录。日志包含时间、级别、线程标识、源码位置和诊断消息；串口字节帧、Modbus 超时、解析错误和数据库错误均可在此追踪。

## 数据与设备生命周期

- 删除设备会在一个数据库事务中清除设备配置、历史采样和报警事件。
- 新设备使用最小可用 ID；清理完成后可复用 ID，不会残留旧设备的历史或活动报警。
- 报警上下限与设备配置一同保存；旧数据库首次启动时自动增加阈值列，并采用温度 15/50 ℃、电压 210/230 V 默认值。
- 当前报警可以确认；确认状态会写入 SQLite，程序重新启动后仍保留。设备恢复正常时报警自动关闭并生成恢复事件。

## 手工集成检查

1. 启动应用，确认主界面显示串口、TCP 客户端及 TCP 模拟服务状态，日志目录中出现 `monitoring.log`。
2. 新建模拟设备，调整温度/电压报警上下限，重启应用后确认设备与阈值保留。
3. 启动模拟设备。模拟值会连续波动并周期性越过高低限；确认越界数值变红、活动报警闪烁、报警计数更新。
4. 选中活动报警并确认，确认闪烁停止；重启后确认仍显示“已确认”。等待模拟值回到阈值内，确认当前报警移除且历史中出现恢复事件。
5. 启动 TCP 模拟服务并连接 Modbus TCP 模拟设备；确认服务与客户端指示灯改变。关闭服务或断开链路，确认设备变为离线并留下超时/断连日志；恢复服务后确认重新上线。
6. 使用可用串口验证自定义协议和 Modbus RTU；分别断开或停止模拟从站，确认离线告警、红灯状态和恢复过程。
7. 打开设备详情，连续切换历史范围并查询，确认窗口可以继续响应；查看日志中数据库连接和查询错误。
8. 删除有历史数据和活动报警的设备后重新添加设备，确认旧记录及活动报警均已清理，ID 可从最小空缺值重新分配。

实际串口步骤需要设备或虚拟串口对；未接硬件时请按 TCP 与模拟数据路径完成可用部分。
